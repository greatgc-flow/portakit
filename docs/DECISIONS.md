# Ratified decisions

- Name: `portakit`. Windows only, Python 3.11+ standard library, one module and a catalog beside it. Initial build: 83 tests; static reviews passed; scope and specification approved unanimously by cc, cx and ag. Final v0.2.1 approval: cc, cx and ag; tests since restructured (173).
- [SPEC](SPEC.md) is the behavioral contract. README summarizes user operation; HANDOFF contains open work.
- Catalog pins use HTTPS URLs and SHA256. Updates follow both version and digest, including downgrades; identical pins skip downloading while the destination exists.
- Destinations are single folders, uniquely owned by state IDs. Never adopt unmanaged folders or follow reparse points, junctions or symlinks.
- Mutating operations hold a root lock, discard stale temps, verify downloads before extraction, and stage before swapping. State write commits the swap; pre-commit failures roll back. Update alone recovers a lone backup; both folders require manual resolution.
- Explicitly preserved paths override packaged files during updates. Opt-in `preserveMissingOnUpdate` merges only missing user/plugin files into the stage, leaving shipped binaries and updated plugin lists intact. Remove deletes all managed data and the backup before forgetting state; it works without a catalog.
- JSON uses one result envelope and exit codes 0–6; help stays human text. No cache, shims, silent/global config seeding or force flag in the MVP; optional per-install recommended profiles require `--recommended`.
- Behavior changes use tests first, red then green; validation is `python -I -m unittest discover -s tests`.

- 2026-10-20: New opt-in `install --recommended` profile seeds minimal editor settings, validates/verifies pinned third-party Notepad++ plugin assets and stages them before atomic commit. No silent plugin install, no automatic plugin upgrades, and no external WinMerge plugin duplication. Strongly prefer catalog SHA pins over mutable/latest URLs.

- 2026-10-20: WinMerge recommended setup reuses the shipped Office unpackers (Excel/Word/PowerPoint/Visio) rather than fetching duplicate/unverified third-party packages. Require those files in the verified vendor ZIP before commit. Enable automatic unpacking using WinMerge's actual `[WinMerge]` INI format and `Settings/PluginsEnabled=1`, `Settings/UnpackerMode=1`. Office COM prerequisites are not installed or guaranteed; these unpackers compare extracted contents, not rendered document formatting.

- 2026-10-20: `configure ID` is an explicit opt-in for applying recommended settings and missing pinned plugin files to an existing *PortaKit-managed* current-pin installation. Uses a private copy, rejects links, preserves unrelated files and state, swaps with rollback, and is idempotent. No implicit update, remote application reinstall, system registry or shell association changes.


- 2026-10-20: Audit of all 3 tools and install/configure/update/remove/cache/registry defaults: retain vendor defaults and pinned SHA integrity; jq gets no editor plugins, no shell menu or PATH changes. Add **explicit, separate** current-user classic Explorer right-click menus for managed portable Notepad++ file editing and WinMerge file/folder comparison; do not enable implicitly in normal install or profile configuration. Use unique HKCU-owned keys, collision refusal, no COM DLL/registry hijacking, log evidence, idempotent register/unregister. Advanced vendor two-selected-item/Windows 11 modern shell integration and full Office COM tests stay in BACKLOG.md.

- 2026-10-20: Add a **separate optional toolset layer** over the current pinned catalog. Categories Common, OS, NW, Dev, Data, Diagnostics and profiles minimal, mes-support, developer, all-curated. Preserve all default tool/config behavior and the existing single-tool CLI. A cross-category membership is deliberate reuse; deduplicate installation by tool ID. `list`/`plan` are read-only; `apply` requires `--yes` and does install-only (no silent update/remove/reconfigure, no registry changes). `--recommended` is explicit for new editor installations only. Zero-tool categories are valid and must not invent NW binaries. Extra OS/NW tools require independent immutable asset pin, SHA256, license/privileges review, smoke tests. See [TOOLSETS](TOOLSETS.md).

- 2026-10-20: **Taxonomy correction supersedes earlier overlapping categories.** v2 defines 10 mutually exclusive *primary functionality* domains; profiles form orthogonal task/role combinations and may include multiple categories and direct pinned tools. Six old category names are **frozen legacy aliases**, and three old profile names retain prior selection results. 8 independently SHA-pinned GitHub release ZIPs are appended (ripgrep, fd, fzf, bat, sd, yq, delta, hyperfine), all individually under 6 MiB compressed per release metadata. End-user installation remains explicit `apply --yes`; ordinary `install`/update/configure unchanged. Five extra immutable pins: 7zr (7z-only), Everything desktop, grepWin portable, Miller, dasel. Category ownership remains mutually exclusive and legacy selectors frozen. 7-Zip full GUI, Everything NTFS index service and hosted GUI acceptance remain opt-in backlog; do not claim an installed ZIP equals service authorization. Research inventory now 108 / 16 pinned / 27 built-in / 65 candidates.

- 2026-10-21: Admit **complete official 7-Zip 26.04 portable GUI/CLI** separately from `7zr`, using exact SHA-256 pinned vendor x64 SFX as DATA, not as an executed Windows installer. Only hash-reverified managed 7zr can list/extract it. Pre/post validation limits path traversal, encrypted/link/special entries and archive bombs; original atomic stage/rollback. No registry file associations or system services. `portable-productivity` has both IDs prereq-first, catalog 17; research 108 (17 pinned / 27 built-in / 64 candidate). User GUI/Explorer integration acceptance still outstanding; hosted CI binary and ZIP operation is not proof of GUI acceptance.

- 2026-10-21: Preserve fully optional, risk-aware **human GUI acceptance** for Everything/grepWin/7-Zip. The default is a no-launch read-only pin/hash check with new local-only evidence and NOT_VERIFIED result; a human interactive review may attest PASS, with independent explicit launch consent and extra Everything first-run-service/index consent. Headless CI can test gate logic, not actual GUI usability. Sysinternals TCPView/PsPing kept metadata-only because company-device use is permitted yet third-party distribution/closed-network repackaging requires independent corporate legal/security approval. Current vetted installable catalog remains at 17.
- 2026-10-30: Admit Sysinternals **TCPView 4.19** (`download.sysinternals.com/files/TCPView.zip`, 1604604 B) and **PsPing 2.13** (single signed `psping64.exe` from `live.sysinternals.com`, 352536 B; not the PsTools suite) as SHA-256 pinned direct-from-Microsoft installs. Basis: user stated direct install from official site is permitted; this is **not** a recorded company legal/OSS approval and does not allow redistribution or bundling. Vendor URLs are mutable, so a hash mismatch fails closed. Not done: PsPing traffic tests (need network owner approval), EULA acceptance registry changes. Catalog 19; research 108 (19 pinned / 27 built-in / 62 research-only).
- 2026-10-30: Scope policy: legal, OSS, security and network-owner approvals for any tool (including Sysinternals) are the **end user's own responsibility**; PortaKit does not track or gate on them. Its contract is correct, hash-verified CRUD (install/list/update/remove) of catalog pins. Live online CRUD of tcpview and psping verified on Windows (temp root, removed afterwards).
