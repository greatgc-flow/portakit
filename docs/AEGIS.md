# Aegis — 선택형 창 정렬 도구

Aegis는 사용자가 지정한 프로세스의 창을 티어·그룹별로 배치하고, 작업 중 바꾼 창을 저장된 정상 위치로 돌려놓는 도구입니다. PortaKit에는 선택형 `aegis` 항목으로 들어갑니다. 설치와 창 조작은 별도 작업이며, 설치만으로 창을 움직이거나 상주 감시를 시작하지 않습니다.

## 실행 환경과 포함 범위

| 구성 | 역할과 요구 환경 |
| --- | --- |
| PortaKit | 기존 Windows / Python 3.11+ 설치·업데이트·제거와 선택 목록을 담당합니다. |
| Aegis 엔진 | `Aegis.ps1`과 사용자 CSV로 직접 사용할 수 있습니다. Windows PowerShell 2.x / CLR 2 호환을 목표로 하며 Python을 사용하지 않습니다. |
| Aegis 메뉴 | `Start-Aegis.cmd`로 별도 PowerShell 호스트를 열고 그 호스트에서 명령을 이어 실행합니다. |
| PortaKit 선택 GUI | 기존 도구 선택·저장 기능을 유지합니다. Aegis 실행이나 창 조작 버튼을 추가하지 않습니다. |

현재 로그인한 사용자의 대화형 데스크톱을 대상으로 합니다. 서비스와 Session 0용 프로그램이 아닙니다. 관리자 권한 상승, PowerShell 2 기능 설치, 실행 정책 우회를 자동으로 수행하지 않습니다. 대상 PC의 승인된 PowerShell 호스트와 실행 정책을 사용합니다.

이 버전은 `4.1.0-ps2`입니다. 버전명의 `ps2`는 호환 목표를 나타냅니다. **실제 Windows PowerShell 2 / CLR 2와 운영 앱에서의 통합 실행은 `NOT_RUN`**이며, 코드·알고리즘·모의 경계 검증과 구분합니다. 폐쇄망의 실측 자료를 반출하거나 제출할 필요는 없습니다.

## 설치와 수동 실행

폐쇄망에서는 승인된 반입 절차로 `Aegis-4.1.0-ps2.zip` 원본을 가져와 설치합니다. 다음 명령은 ZIP을 데이터로 읽고 카탈로그 SHA-256을 검증하며, Aegis를 실행하지 않습니다.

```powershell
python -I portakit.py --archive "D:\Approved\Aegis-4.1.0-ps2.zip" install aegis

# 설치 후 사용자가 별도로 실행
.\portable\aegis\Start-Aegis.cmd
```

네트워크 사용이 허용된 환경에서는 기존 `python -I portakit.py install aegis`도 사용할 수 있습니다. 다운로드 주소는 자체 버전 ZIP의 전체 Git 커밋 SHA를 포함하는 주소이고, 바이트 무결성은 별도의 카탈로그 SHA-256으로 확인합니다. 변경 가능한 브랜치 ZIP이나 `latest` 주소로 대체하지 않습니다. 현재 핀의 기준은 [catalog.json](../catalog.json)입니다.

Python을 사용할 수 없는 PS2 PC에서는 같은 ZIP을 승인된 위치에 직접 풀어 메뉴 또는 엔진을 실행할 수 있습니다. 이 경우 PortaKit의 설치 상태 기록은 생기지 않으며, 직접 배치한 파일의 관리도 별도입니다.

## 프로그램과 사용자 데이터

기본 설치 루트가 `portable`일 때의 경로는 다음과 같습니다.

| 경로 | 내용 | 업데이트·제거 시 처리 |
| --- | --- | --- |
| `portable\aegis\` | 엔진, 메뉴, CSV 원본 예시, 설명서, 라이선스와 패키지 해시 목록 | PortaKit 관리 대상입니다. 업데이트로 교체되고 `remove aegis`로 삭제됩니다. |
| `portable\aegis-data\Aegis.Processes.csv` | 실제 사용자 프로세스·티어·크기 규칙 | 메뉴가 처음 없을 때만 원본 예시를 복사합니다. 기존 파일을 덮어쓰지 않습니다. |
| `portable\aegis-data\profiles\` | 사용자가 명시적으로 저장한 홈 프로필 | Aegis 설치·업데이트·제거 대상 밖에 두고 보존합니다. |

첫 메뉴 실행으로 사용자 데이터 폴더를 준비한 후, **`aegis-data`의 CSV를 편집**하세요. 프로그램 폴더에 있는 CSV는 배포 원본입니다. 사용자 데이터 위치는 프로그램 폴더의 형제 폴더로 계산하므로 다른 PortaKit 루트에서도 같은 구조를 사용합니다.

별도 데이터 위치가 필요하면 다음처럼 명시할 수 있습니다.

```powershell
powershell.exe -NoProfile -File .\portable\aegis\Aegis.Menu.ps1 -DataDirectory "D:\AegisData"
```

프로그램 설치 폴더 내부를 사용자 데이터 위치로 지정하지 않습니다. 메뉴는 그 위치와 연결점·심볼릭 링크 경로를 거부합니다. 기본 형제 폴더에 쓸 수 없으면 오류와 함께 다른 `-DataDirectory`를 안내하며, 임의의 사용자 프로필 경로로 조용히 전환하지 않습니다. 지정한 다른 경로 역시 별도 관리 도구가 삭제하는 디렉터리 밖으로 선택하세요.

업데이트하거나 제거하기 전에는 메뉴를 종료하세요. 사용자 데이터는 남으므로 재설치 후 같은 데이터 위치를 지정하면 규칙을 다시 사용할 수 있습니다. 홈 프로필은 명시적으로 저장한 파일만 남습니다. 폴더 전체를 수동으로 지우거나 다른 관리 도구가 지우는 작업까지 보존하는 기능은 아닙니다.

## 프로세스별 크기와 티어 지정

CSV의 핵심 항목은 다음과 같습니다. 전체 열과 제한은 [엔진 설명서](../tools/aegis/README_ko.txt)에 있습니다.

| 항목 | 의미 |
| --- | --- |
| `ProcessName` | 실행 파일 이름을 정확히 지정합니다. `.exe` 유무와 대소문자를 정규화하며 와일드카드·정규식을 실행하지 않습니다. |
| `ClassName`, `Title` | 필요할 때 같은 프로세스의 여러 창을 구분하는 정확한 조건입니다. |
| `Tier` | `3`, `2`, `1` 순서로 최소 공간과 가중 배분을 계산합니다. |
| `GroupId`, `GroupPriority`, `GroupWeight` | 티어 안의 그룹과 그룹 우선순위·여유 공간 배분 비중입니다. |
| `Priority` | 그룹 안에서 창을 수용하는 순서입니다. Windows CPU 우선순위와 무관합니다. |
| `SizeMode`, `Width`, `Height` | 현재 크기 유지(`Preserve`), 지정 크기(`Exact`), 선호 크기(`Preferred`), 셀 채우기(`Fill`)를 선택합니다. |

예를 들어 동봉된 `terminal` 규칙의 `ProcessName`을 실제 작업 앱 이름으로, `Width`와 `Height`를 `1000`, `700`으로 바꾸면 됩니다. 크기는 Win32가 관측한 **창 바깥 사각형**이며 클라이언트 영역 크기가 아닙니다. 모든 DPI 환경에서 물리 픽셀과 같다고 가정하지 않습니다. `Exact` 크기를 앱이나 배정 영역이 수용하지 못하면 보류합니다. 여러 규칙이 한 창에 맞으면 CSV에서 먼저 나온 규칙을 사용합니다.

티어 내부는 그룹, 그룹 내부는 격자 셀로 나눕니다. 우선순위는 각 계층 안에서 적용되며 전역 최적 사각형 패킹을 보장하지 않습니다. 작은 창도 정상적인 대상이며, `Preserve`는 크기를 유지한 채 이동합니다. 창의 크기 변경 제약을 확인할 수 없으면 크기 변경을 보수적으로 제한하고 이유를 보고합니다.

## 한 호스트에서 사용하는 작업 순서

메뉴에서 필요할 때 명령을 선택합니다. 시작 시 자동 정렬, 백그라운드 폴링, 예약 실행을 추가하지 않습니다.

1. `Inspect`로 규칙 매칭, 티어·그룹, 보류 이유를 확인합니다.
2. `Arrange` 미리보기를 확인한 뒤 `Arrange`를 선택해 최초 정상 홈을 만듭니다.
3. 작업 중 창을 확대하거나 이동한 뒤 `Return`으로 홈 위치와 크기로 복귀합니다. 현재 작업 크기를 유지하려면 `KeepSize` 복귀를 선택합니다.
4. 기존 티어 안의 그룹을 다시 나누거나 기존 그룹 안의 창을 다시 나눌 때 `Reflow`의 범위를 지정합니다. CSV 규칙·크기 또는 모니터 구성이 바뀌면 전체 `Reflow`를 사용합니다.
5. 다음 세션에도 홈을 사용하려면 `SaveProfile`로 저장하고 새 메뉴 세션에서 `LoadProfile`로 불러옵니다. 기본 이름은 `home`이며 `profiles\home.xml`로 저장합니다. 기존 이름을 덮어쓰려면 메뉴에서 `YES`를 입력해야 합니다. 파일 불러오기만으로 창을 움직이지 않습니다.

`Return -KeepSize`는 현재 크기가 그룹 경계를 벗어나거나 다른 홈과 겹치면 보류합니다. 국소 `Reflow`는 선택한 기존 경계를 넓히지 않고 다른 티어·그룹의 홈을 유지합니다. 새 창의 수용 불가와 기존 홈의 수용 불가를 구분하며, 실제 OS 조작이 시작된 뒤 여러 창을 하나의 원자적 작업처럼 되돌릴 수 있다고 보장하지 않습니다.

Undo와 미완료 비동기 요청(`Pending`)은 **같은 PowerShell 프로세스의 메모리**에 있습니다. 메뉴가 각 명령을 새 PowerShell로 실행하지 않는 이유입니다. `Undo`는 마지막 변경 결과와 현재 상태가 맞을 때만 한 단계 되돌립니다. 홈 프로필 저장은 Undo·Pending 저장이 아닙니다. 메뉴를 닫으면 메모리 상태는 사라집니다.

`Pending`은 이동 요청의 완료를 확인하지 못했다는 뜻이며 취소를 뜻하지 않습니다. 메뉴는 이 상태에서 `Inspect`만 허용하고 일반 종료 선택도 보류합니다. 호스트 창을 강제로 닫거나 새 메뉴로 재실행해 우회하지 마세요. 메뉴 중복 실행 방지와 엔진의 실행 중 잠금이 임의로 시작한 별도 엔진 호스트의 전체 수명을 통제하는 것은 아닙니다.

## 최소화와 트레이 앱

숨김·최소화·트레이 상태의 창을 Aegis가 임의로 복원하지 않습니다. 앱 자체의 정상 동작으로 창을 표시한 후 사용자가 `Return` 또는 `Arrange`를 실행합니다. 숨은 창의 홈 슬롯은 보존하며, 다른 창이 평상시 정렬에서 그 자리를 차지하지 않습니다.

동일 HWND가 돌아오면 기존 홈을 사용할 수 있습니다. 앱이 HWND를 새로 만들면 이전 창이 사라졌는지, 규칙과 미연결 슬롯이 유일한지 확인한 경우에만 연결합니다. 같은 프로세스의 여러 창이 모호하면 보류합니다. 명시적인 `ReleaseAbsent` 재분할만 예약을 해제합니다.

## 선택 목록과 기존 프로필

`aegis`의 유일한 기본 분류는 `automation`입니다. 다른 분류에 중복 등록하지 않으며 새 기본 프로필도 만들지 않습니다.

| 선택 방법 | Aegis 포함 여부 |
| --- | --- |
| 개별 `aegis`, `automation` | 포함 |
| `engineering`, `all-curated` | 기존 프로필이 `automation`을 확장하므로 포함 |
| `essentials`, `workstation`, `lightweight` | 직접 지정된 기존 도구 목록을 유지하므로 자동 추가 없음 |
| 기존 별칭 `common`, `os`, `nw`, `dev`, `data`, `diag` | 기존 고정 목록 유지 |
| 이미 저장한 개인 키트 | 기존에 저장한 명시적 선택을 유지하며 새 카탈로그 항목을 자동 추가하지 않음 |

따라서 `engineering` 또는 `all-curated`를 새로 계획·적용하는 사용자는 `plan`에서 Aegis 포함을 확인할 수 있습니다. 설치 목록 포함은 실행 동의나 자동 창 조작으로 이어지지 않습니다.

## 업데이트·제거와 검증 한계

```powershell
# 카탈로그와 승인된 ZIP이 같은 버전·해시이면 기존 설치는 변경 없음
python -I portakit.py --archive "D:\Approved\Aegis-4.1.0-ps2.zip" update aegis

# 프로그램만 제거; 형제 aegis-data 폴더는 유지
python -I portakit.py remove aegis
```

배포 ZIP은 허용된 런타임 파일만 담고, 개발용 분할 소스·테스트·이전 증적·사용자 데이터는 제외합니다. 설치 관리자는 기존 ZIP 추출·SHA 검증·상태 기록·업데이트/제거 경로를 그대로 사용합니다. 운영 앱 실행이나 창 이동을 설치 후크에 넣지 않습니다. 동일 핀 업데이트는 상태 기록과 설치 폴더 존재를 확인한 뒤 건너뛰므로, 이미 설치된 모든 파일의 무결성을 재검사하는 명령으로 해석하면 안 됩니다.

검증은 재현 가능한 패키징, 실제 번들의 오프라인 설치·업데이트·제거, 해시 불일치 거부, 사용자 형제 데이터 보존, 분류/선택 경계, 순수 배치 계산과 모의 native 경계로 나눕니다. 이 검증으로 실제 PS2 실행, 실제 앱별 최소 크기·트레이 동작, 다중 DPI 데스크톱, 운영 서버의 CPU·메모리·지연 수치를 입증하지는 않습니다. 이 항목들은 `NOT_RUN` 또는 `N/A`로 남기며 100점 운영 안정성으로 환산하지 않습니다. 상주 폴링을 두지 않고 각 명령의 탐색·후보·관측 예산을 제한하는 설계와 실제 자원 사용량 측정도 구분합니다.

원본 소스와 자세한 동작 계약은 [tools/aegis](../tools/aegis/) 및 [README_ko.txt](../tools/aegis/README_ko.txt), 설치 관련 회귀는 [test_aegis_integration.py](../tests/test_aegis_integration.py)에서 확인할 수 있습니다.
